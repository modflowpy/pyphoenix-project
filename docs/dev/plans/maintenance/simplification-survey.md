## Higher value

### 1. Rows come in two forms, so most code that reads them does the work twice

A list's rows are either a `list[Item]` or an `ItemTable`, and there are 15
`isinstance(..., ItemTable)` branches to cope with that.

- **`package.py`:** the helpers at the bottom of the file each have both paths:
  `_column_values`, `_lengths`, `_any_set`, `_boundnames`, `_rows_ts_names`
  and `_table_dict`.
- **`period_lists.py`:** each conversion direction has a column-wise fast path
  and a row-by-row path. `_dense_tables` (185 lines) sits beside the general
  loop in `to_dataset`, and `_sparse_tables` beside `_from_sparse`.
- **Fix:** give a plain list the same interface `ItemTable` has
  (`values(name)`, `any_set`, `columns`), or store every tabular list as an
  `ItemTable`. Then the helpers and the duplicate paths can go.
- **Timing:** right after the `Item`→`Record` merge.

### 2. The output readers have a dis copy and a disv copy of each function

- `utils/cbc_reader.py`: `_open_cbc_dis` / `_open_cbc_disv`, and
  `open_imeth1/6_budgets` / `disv_open_imeth1/6_budgets`.
- `utils/heads_reader.py`: `_open_hds_dis` / `_open_hds_disv`.
- The copies differ only in shape, dims, coords, and whether the result is
  wrapped in `UgridDataArray`.
- **Fix:** pass a small object carrying those four things and keep one copy
  of each function. That removes roughly 250 lines.
- Low risk: `test/mf6/test_mf6_output_readers.py` covers it.

### 3. `utils/grid.py` repeats a lot between `StructuredGrid` and `VertexGrid`

- 100 of the 118 lines in `StructuredGrid._layered_mesh_dataset` also appear
  in `VertexGrid.to_xarray`.
- The overrides for `top`, `botm`, `idomain` and `delz`, the `legacy`
  switching, and `_topology` and `ugrid` are close copies too.
- **Fix:** move the shared code into a base class or mixin.
- `StructuredGrid.from_dis` / `VertexGrid.from_dis` repeat `dis.to_grid()`,
  and only tests call them (`test_mf6_component.py`). Make them call
  `dis.to_grid()`, or remove them.

### 4. Writing JSON or TOML is broken, and the layer around it is mostly left over

- `Ic(...).write(format="json")` raises `TypeError: _write_json() got an
  unexpected keyword argument 'context'`; TOML fails the same way (checked
  2026-10-28). No test covers either.
- `_load_json` and `_load_toml` (`flopy4/mf6/__init__.py`) call the cattrs
  `Converter` in `converter/__init__.py`, which has no structure hook for
  `Component`. That converter's only job is to register
  `unstructure_component`.
- **Fix:** either fix and test JSON/TOML, or delete them. Deleting also
  removes cattrs, the `flopy4/uio.py` registry indirection, and
  `COMPONENT_CONVERTER` (`test_mf6_codec.py` uses it; switch those to
  `unstructure_component`).
- **Related:** `Package.load` duplicates `_load_mf6` and bypasses the
  registry, so there are two ways to load an MF6 file. Check against
  `simplify-converter`, which touches `package.py`.

### 5. The writer still works out each value's type from the Python value

- It uses the `isinstance` chain in `codec/filters.field_type` and its two
  calls in `codec/writer/templates/macros.jinja`. This is still so on
  `simplify-converter`, where egress already knows each field's DFN type.
- **Fix:** have egress pass that type along with each value, then delete
  `field_type`.
- Pairs naturally with [`writer-dead-code.md`](../archive/writer-dead-code.md).

## Medium

### 6. `to_dict` has two different implementations

- `Component.to_dict` and `Package.to_dict` exclude different fields and
  handle aliases differently.
- `Component.to_xarray` and `_collect_child_griddata_datasets` hide errors
  with three nested `except Exception: pass` blocks, so a failure just drops
  data without saying so.

### 7. The discretization method mixins repeat themselves

- `dis_methods.py`, `dis2d_methods.py`, `disv_methods.py`,
  `disv1d_methods.py`, `disv2d_methods.py`.
- Each defines `_LENGTH_UNITS` again, and copies the same georeference
  handling (xorigin, yorigin, angrot, crs, length units) in both directions.
- **Fix:** one helper each way would cover all five. `Dis2d` is essentially
  `Dis` with a single layer.

### 8. `netcdf.py` keeps a parallel model of the package classes

- `_pkgclass` re-implements looking up a component class by name, which
  `get_fnames` in `component.py` already does.
- `_PackageSpec` re-derives field information that `spec` already provides.
- Export goes from a metadata dict through pydantic validation to xarray.
- A design question more than a quick cleanup. Building the export straight
  from `Package.to_xarray()` might remove a lot; not checked against the
  NetCDF tests (`test_mf6_netcdf.py`, `test_mf6_netcdf_cf_conventions.py`).

## Low / internal

### 9. Codegen has one very large function

`build_component_spec` in `utils/codegen/make.py` is 571 lines, and a
seven-line comment paragraph appears twice in it (on `_repeating_blocks`).
Split it into the four field buckets its own comments describe.

### 10. Small duplicates

- `period_lists._is_cellid` is the same as `item._is_one_cellid`.
- `_LENGTH_UNITS` is defined five times (see #7).
