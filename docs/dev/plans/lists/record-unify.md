## Terminology

All of these are records in DFN terms:

- **Row records**: `Item` subclasses (`item.py:507`), one per list-block row.
- **Line records**: plain `Record` subclasses (`record.py:186`), one per
  keyword line in a non-list block (NPF `XT3D [RHS]`, OC `Format`, TS
  `NAMES`).

The split is historical, not semantic. Steps 1–3 unify how fields are
declared and how arrays are detected; step 4 removes the split.

### Row layout: one rule, positional, following MF6

The DFN spec's rule (dfnspec.md, inline arrays): **a row's layout is fixed
by the component's dimensions, except for its last field.** An inline array
sized only by dims may be anywhere; one whose width varies by row
(self-sizing, sized by a sibling, or by a lookup) must be last.

Reading a file row and building an item from a Python tuple are the same
problem: split a sequence of values into fields. Only the per-field
conversion differs (file tokens are strings, indices/cellids 1-based;
Python values are typed, 0-based). So:

- **One layout function** shared by both paths, then a converter per
  source.
- **No value sniffing, anywhere.** Today `infer_ncelldim` (`item.py` ~362)
  and `construct_item` both take a trailing non-numeric string as a
  boundname. Remove that. MF6 never inspects a value to decide what it is;
  every width comes from package context.
- **Except a union's arm**, which its own tokens choose, as in MF6: a
  keyword arm by its keyword; OBS's `id` (cellid | index | string, not the
  last field: `id2` follows) by whether its first token is a number (a
  cellid/index, `ncelldim` or 1 tokens) or not (a boundname, 1 token).
  That's local to the field: still no other field, row or block is
  consulted.

Given a row's values and the package context, walk the fields in order:

1. **Each field takes its width.** A scalar: 1. A cellid: the `ncelldim`
   of its grid. A dim-sized inline array: its dims' value (aux by
   `auxiliary`, GNC `cellidsj` by `numalphaj`, EVT `pxdp` by `nseg-1`).
2. **Flat or tupled** (Python input only; file tokens are always flat).
   If the next value is a sequence (tuple/list, not str) or `None`, it is
   the whole field (`None`: an unset optional field, or an `allow_zero`
   cellid that refers to no cell). Otherwise the field takes its width in
   scalars. So
   `((0, 2, 3), 1.0)` and `(0, 2, 3, 1.0)` are both a CHD row; the same
   for aux and any other known-width array, field by field.
3. **The last field**, if its width varies by row, takes the rest of the
   row, minus a boundname if there is one.
4. **A boundname is present iff the package's `boundnames` option is
   set.**
   - Reading a file: strict; the option is in the file.
   - Python input: the option defaults to `False` and nothing sets it from
     the rows today, while `to_tokens` writes a row's boundname regardless,
     so users may pass boundnames without the option. As in approach (a)
     below: if the option is unset and rows have exactly one value more
     than the layout allows, that value is a boundname and the package
     sets `boundnames=True` (like it sets dims from rows). Any other
     surplus is an error. Decided by count, never by the value's type.
   - Overlaps [`boundname-plan.md`](../archive/boundname-plan.md) step 2 (same repo), which this
     supersedes: with the option known, the boundname takes the last token
     and an optional group is counted from what's before it, so there's no
     tie to break and its type-check tiebreaker (and open question) goes.
     Its other steps (`""` -> `None`, token text, quoting, empties) are
     independent of this.
5. **An optional untagged group** (EVT's `petm0`) is present iff its
   gating option is set (`SURF_RATE_SPECIFIED`), if the DFN/flopy4 records
   the gate; otherwise decided by the value count, as today (still
   positional).

### Context

The layout needs package context, which the package has where it coerces
rows (`Package._coerce_item_list`, `package.py` ~363, called from
`_init_item_lists` and the DataFrame path ~682; make it an instance method
and pass the context). Bundle it in one row-context object rather than
`from_tokens`' growing keyword list: `ncelldim` per grid, dim sizes,
`boundnames`, option gates, and `select` for lookups (devtools'
`dim_value(..., select=...)`).

**Unknown grid** (a package built standalone, e.g. `Chd(...)` before it's
added to a model, doesn't know `ncelldim`): agreed approach (a) —
**infer the width from the value count when it's the only unknown width**
(aux and boundnames are known from options, so usually it is). This is
`infer_ncelldim` minus the value sniffing. If ambiguous (an unknown
optional group, or a row-varying last field), raise, asking for the
cellid as a tuple or for the package to be attached to a model. Rejected:
(b) deferring coercion until the package has a parent.

**Without a package** there's no context, so a standalone item takes one
value per field (plain attrs init); flat splitting is only done by the
package.

### API

- `construct_item` (free function since #349, for no design reason)
  becomes a classmethod mirroring `from_tokens`, e.g.
  `Item.from_values(values, context)`. Both call the shared layout.
- Union dispatch (`construct_union_item`, `dispatch_union_item`) stays a
  free function, since it picks the arm class from the row's keyword; it
  then calls the arm's classmethod.
- `construct_item` no longer needs `_tail_fields` / `_dim_counted` /
  `_sized_by_*` to find "the field that takes the rest": that's decided by
  position (rule 3).
- Widths are validated by the package after construction: dims already
  (`dim_input`/`dim_value`, `package.py` ~355); add `select` there so
  lookup-sized arrays are checked too (`len(ic) == packagedata.ncon(ifno)`),
  which isn't checked today (confirm).
