## Decisions (agreed 2026-11-04)

1. **Typed loader on its own branch, kept current** (revised 2026-11-04).
   Two branches:
   - `simplify-converter`: the basic loader and egress only, on develop.
   - `typed-loader`: stacked on `simplify-converter`, adding `_TypedLoad`
     and its grammar work back, with every develop port done there too.
     Rebased whenever `simplify-converter` or develop moves, so the two
     loaders stay comparable (rerun `loader-comparison.md` there later).
   - `simplify-converter-backup` → `f46cfeca`: the pre-rebase backup, and the
     source the typed commits are rebuilt from.
   - Consequence: keep the `ComponentLoad` / `_Load` split on
     `simplify-converter` (the typed branch subclasses it), and keep the
     hooks `_TypedLoad` overrides, even though the basic branch has one
     subclass. Don't fold it.
2. **The rebased branch carries:** stored DFNs + `spec` helpers, the basic
   loader rewrite (`_Load`), the one egress path (`_Unstructure`), header
   kinds (D7), D1-D4, the STO period representation (decision 1).
3. **On `simplify-converter` only, typed-loader things revert to develop's state** (they come back, current, on `typed-loader`): develop already has
   `typed.lark`, the 136 generated grammars, `loads_typed`, the typed
   transformer, `_check_typed_grammar` and parse benchmarks. Those stay
   exactly as develop has them (regenerated by sync). Dropped from the branch:
   - `converter/ingress/typed.py` (`_TypedLoad`), `test_mf6_typed_loader.py`;
   - `LoadContext.loader`, `load(..., loader=)`, the tests' `--loader` option;
   - B1 (rule names after class attributes), B3 grammar skips, B4 on-disk
     parser cache (develop's lark `cache=` / `__lark_cache__` stays);
   - the typed parts of D2 / D7 / STO commits that only served `_TypedLoad`
     (keep any grammar change develop's `loads_typed` corpus check needs).
   - `ComponentLoad`: keep (decision 1).
   - All of the above returns on `typed-loader` (see "The typed branch").
   - `loader-comparison.md`: keep as a report; rerun on `typed-loader` later.

## Mechanics

Squash, rebase once, then build history forward. Avoids re-resolving
`structure.py` in many of the 43 commits.

1. `git branch simplify-converter-backup f46cfeca` (backup of the pre-rebase branch).
2. In the worktree (clean): `git reset --soft d14e5fb2`, commit everything as
   one commit "Simplify the converter (squashed from simplify-converter-backup)".
3. `git rebase origin/develop`. Simulated merge conflicts in 16 files:
   - `benchmarks/report.py`, `benchmarks/test_parse.py`
   - `flopy4/mf6/__init__.py`, `component.py`, `package.py`, `spec.py`,
     `external.py`
   - `converter/ingress/structure.py`, `converter/egress/unstructure.py`
   - `codec/reader/grammar/typed.lark`, `codec/reader/parser.py`,
     `codec/reader/transformer/typed.py`
   - `utils/codegen/make.py`, `utils/codegen/templates/package.py.jinja`
   - `test/mf6/test_mf6_codec.py`, `test/mf6/test_mf6_reader.py`
   Resolution rule: typed/grammar/parser/benchmark files → take develop's
   (`--theirs` side = develop during rebase is `--ours`; check). Generated
   classes, grammars, `dfns/`, snapshots → take develop's for now, regenerate
   in step 6. Converter/spec/codegen → the branch's structure, with develop's
   behavior ported (next section). Getting it importable and the smoke tests
   mostly passing is enough for this commit; the ports can be follow-up
   commits if cleaner.
4. Commit: drop the typed loader (decision 3), if not already done in 3.
5. One commit per develop feature ported (table below), each with its
   tests green.
6. Regenerate: `pixi run -e dev` sync (check develop's command; with the
   devtools pin develop has), stored DFNs included. Update load and
   written-file snapshots; review every snapshot diff, expect only field
   order (S2) and STO's value.
7. Docs commit: update the branch's plan (both copies, see "Docs").

Verify after 5 and 6: smoke, `test_mf6_io_roundtrip.py`,
`test_mf6_load_all_models.py`, `test_mf6_codec.py`, `test_mf6_reader.py`,
`test_mf6_sync.py`, `test_mf6_codegen.py`, `test_mf6_dfn.py`,
`test_mf6_external_arrays.py`, `test_mf6_loader.py`, legacy/integration tests.

## The typed branch

After `simplify-converter` is rebased and green (steps 1-7):

8. `git switch -c typed-loader simplify-converter` (new worktree under
   `.claude/worktrees/typed-loader`).
9. Bring the typed work back from `simplify-converter-backup`: the diff of
   `simplify-converter-backup` restricted to typed files (`converter/ingress/typed.py`,
   `test_mf6_typed_loader.py`, grammar generation/templates/filters/names,
   `parser.py`, `transformer/typed.py`, `load_context.py` `loader`, the
   tests' `--loader`, benchmarks), applied and resolved against the new base.
   Commits by phase: S1 loader switch; B1 rule names; B2/B3 typed load; B4
   parser cache; typed parts of D2/D7/STO.
10. Port every row of the table below into `_TypedLoad` / the typed
    grammar and transformer too (binary lists, `ListIO`, #526 rows, #534
    text tokens in the typed transformer, #525 trailing period blocks, ...).
11. Parser cache: develop's lark `cache=` (`__lark_cache__`) vs the
    branch's B4 user-dir cache keyed by grammar text. Pick one on this
    branch; don't keep both.
12. Regenerate grammars; check the corpus loads the same under both
    loaders (`--loader typed`); update the plan's B/C sections.

Upkeep: when `simplify-converter` changes, rebase `typed-loader` onto it;
when develop changes, rebase `simplify-converter` first, then
`typed-loader`. Any change to `ComponentLoad` or the shared hooks needs
the typed side checked in the same sitting.
