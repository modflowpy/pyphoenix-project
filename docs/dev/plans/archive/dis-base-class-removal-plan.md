# Removing DisBase: generating the discretization packages

Follow-up to the TDIS/NCF work on `codegen-mixins`
([`codegen-base-class-removal-plan.md`](codegen-base-class-removal-plan.md)). Same goal: generated classes carry
no hand-written structure, and flopy API methods come from method-only
mixins listed in codegen's `MIXINS` table.

**Status:** planned; nothing implemented.

## Current state

- `flopy4/mf6/gwf/disbase.py` (`DisBase(Package)`):
  1. declares derived dimensions `nlay`/`nrow`/`ncol`/`ncpl`/`nvert`/`nodes`
     as `init=False` fields, which subclasses override or set in post-init
  2. `_coerce_griddata()`: list → ndarray, repeat a per-layer value
     (size `nlay`) across `ncpl` for `layered` arrays, flatten anything with
     more than one dimension, then `_broadcast_griddata()`
  3. `write()`: sets `ncf6_filerecord` from an attached `Ncf` child, then
     writes the child at full precision
  4. `to_grid()` / `get_dims()` stubs
- Hand-written `Dis`/`Disv` in `gwf/`, identical copies in `gwt/` and `gwe/`,
  and `prt/` copies without ncf and with `netcdf=False`. Each has its own
  `get_dims`, `to_grid`, `from_grid`. Disv adds `iv`/`xv`/`yv`,
  `cell2ddata`/`Cell2dRecord` and the `disv_to_grid_cell2d` /
  `grid_to_disv_cell2d` helpers.
- No Disu class exists.
- The models annotate `dis: DisBase | None`.
- `dfn2py._SKIP` lists `gwf-dis`, `gwf-disv`, `gwt-dis`, `gwe-dis`,
  `prt-dis`. The other hand-written disv modules survive regeneration only
  because `--existing-only` skips files without the autogenerated header.

## Findings

### What codegen produces today

Generated into a scratch directory from the dev3 DFNs with the skip list
emptied. The fields are close to the hand-written ones. The gaps:

| | hand-written | generated |
|---|---|---|
| dis `top` shape | `("ncpl",)` | `("ncol", "nrow")` |
| dis `botm`/`idomain` shape | `("nodes",)` | `("ncol", "nrow", "nlay")` |
| disv `botm`/`idomain` shape | `("nodes",)` | `("ncpl", "nlay")` |
| derived dims | `init=False` fields + `get_dims` | none |
| ncf path | `ncf6_filerecord` | `ncf_file` |
| grb path | none | `grb_file` |
| ncf child | `ncf: Optional[Ncf]` | none |
| disv `cell2d` | raw tuples, `init=False` | `list[Cell2d]` with `icvert: int` (bug) |
| disv `vertices` | `list[Vertices]` built from `iv`/`xv`/`yv` | `list[Vertices]`, `dim="nvert"` |
| defaults | `xorigin=0.0`, `idomain=1` (dis) | `None`, `None` |

### The DFN declares the derived dimensions

`Component.dims` carries each dimension's expression:

- gwf-dis: `ncpl = nrow * ncol`, `nodes = nlay * nrow * ncol`, `ncelldim = 3`
- gwf-disv: `nodes = nlay * ncpl`, `ncelldim = 2`
- gwf-disu: `ncelldim = 1`, and component-scoped `njas = (nja - nodes) / 2`
- olf-dis2d: `ncpl = nodes = nrow * ncol`

So `get_dims` and the derived dimensions can be generated. Scope doesn't
pick out the grid packages: `maxbound` and friends are model-scoped too.
Departure 4 of the TDIS plan still holds (a default `get_dims` on every
package makes them all providers and names collide), so which components
provide dimensions stays explicit in codegen config.

### Flat griddata

Griddata is stored flat: `("nodes",)` or `("ncpl",)`. That's a flopy4
convention, not a necessity. It matches MF6's own storage, and every other
package's DFN already gives griddata as `nodes` (NPF `k`, IC `strt`, ...).
Only the dis/disv DFNs spell out the structured shape, in Fortran order
(`ncol, nrow, nlay`). Egress reshapes a flat layered array to
`(nlay, ncpl)` to write `LAYERED`, and `netcdf.py` reshapes flat data
per-dimension. If dis stored `(nlay, nrow, ncol)` instead, `botm` and NPF
`k` would have different shapes on the same grid. Keep flat.

### Disv follows the DFN

The DFN has `vertices` (rows of `iv`, `xv`, `yv`) and `cell2d` (rows of
`icell2d`, `xc`, `yc`, `ncvert`, `icvert...`). Hand-written Disv has its own
inputs for the same data, which go away, as in OC and TDIS:

- `iv`/`xv`/`yv` (the `vertices` columns as separate 0-based arrays) are
  replaced by `vertices`. Columnar input still works through list
  coercion: `Disv(vertices={"iv": iv, "xv": xv, "yv": yv})`.
- `cell2ddata`/`Cell2dRecord` is replaced by `cell2d`, a list of the
  generated `Cell2d` Item. Hand-written Disv couldn't use a generated Item
  for this only because of the `icvert` bug below.

Callers (~70: tests, `utils/grid.py`, `docs/examples/circle.py`) move to
`vertices=` / `cell2d=`. No aliases.

### Codegen bug: `icvert` generated as a scalar

In the DFN, `icvert` is an integer `Array` with `shape=["ncvert"]`, the last
field of the `cell2d` record: an inline array sized by an earlier column of
the same row. Each row has as many trailing values as its `ncvert`:

```
CELL2D
  1  0.5  0.5  4  1 2 5 4
  2  1.5  0.5  3  2 3 5
```

Codegen turns every record field into a scalar Item attribute, so it emits
`icvert: int`, which can't hold the row's vertices. It should emit an
array-typed column. Fix:

- Item: `icvert: tuple[int, ...]` with `shape` metadata naming the count
  column (`ncvert`); index renumbering applied per element (as cellid
  already does).
- Ingress: the row reads the count, then that many values (or the rest of
  the line; a variable-length column must be last).
- Egress: flatten the tuple into the row.
- `ncvert` derived from `len(icvert)` when omitted.
- Codegen fails on a variable-length column that isn't last.

Disu's `cell2d` has the same shape. Check the corpus for other inline
arrays in records; they get the same treatment.

### The subpackage link isn't in the dev3 DFN

The legacy `gwf-dis.dfn` starts with `# mf6 subpackage utl-ncf`. The dev3
spec drops it: `ncf_filerecord` is a plain record (`ncf6` keyword +
`ncf6_filename` file), and `utl-ncf`'s parent is `sim-nam`. So nothing in
the dev3 DFN says this record names an NCF package. Options:

- derive it: a `filein` record whose keyword is `<abbr>6` names `utl-<abbr>`
  when that component exists (`ncf6` → `utl-ncf`, `ts6` → `utl-ts`,
  `obs6` → `utl-obs`). No config, but it also turns TS/OBS file records
  into child fields, which is a bigger change than this plan needs.
- a codegen table, like `MIXINS`: `SUBPACKAGES = {"ncf_filerecord":
  "utl-ncf"}`. Smallest; NCF only.
- carry the annotation through the devtools migration (e.g. a `subpackage`
  attribute on the record). Right long-term, but it's devtools work.

Start with the codegen table; move to the devtools attribute later. The
devtools fix is written up in `../modflow-devtools/subpackage-links-plan.md`
(`File.component`, set from both legacy annotations).

### Lists → arrays

`Package._broadcast_griddata` handles scalars, ndarrays and empty dicts, and
leaves a list alone. `_coerce_griddata` converts lists so `Dis(delr=[...])`
works. Generated packages have the same gap today (`Npf(k=[...])` stays a
list), so the conversion belongs in `Package`.

## Design

### Codegen

1. **Canonical griddata shapes.** For a component declaring derived dims, a
   multi-name griddata shape whose names are exactly the factors of a
   declared dimension's product expression becomes that dimension:
   `(ncol, nrow)` → `ncpl`, `(ncol, nrow, nlay)` → `nodes`,
   `(ncpl, nlay)` → `nodes` (via `nodes = nlay * ncpl`). Match on the
   multiset of names, not order. Fail codegen if a griddata shape has more
   than one name and matches nothing. (Alternatively devtools normalizes
   these in the dev3 migration; decide with the devtools work.)
2. **Derived dimensions.** Emit a `ClassVar` of the component's
   non-trivial dim expressions, e.g.
   `_derived_dims = {"ncpl": "nrow * ncol", "nodes": "nlay * nrow * ncol",
   "ncelldim": "3"}`, and `init=False` read-only properties for the ones
   that aren't DIMENSIONS fields. Arithmetic only (`+ - * /`, names,
   integer literals); evaluate with a small parser, not `eval`. Skip
   lookups like `sum(packagedata.nlakeconn)`.
3. **Dimension providers.** A `GridDimsMethods` mixin supplies
   `get_dims()` from the DIMENSIONS fields plus `_derived_dims`. Listed in
   `MIXINS` for the grid packages only (dis, disv, disu, dis2d, disv1d,
   disv2d). TDIS keeps its own.
4. **Subpackage fields.** For an options path record listed in a
   codegen `SUBPACKAGES` table (NCF only, for now; see above), emit `ncf: Optional[Ncf]` next to the path
   field. `Package.write` syncs the path from the child and writes the
   child, generalizing `DisBase.write`. The full-precision rule for NCF
   coordinates moves to `Ncf` (via `NcfMethods` or a field-level metadata
   flag) rather than living in the parent.
5. **Array columns in Items** (the `icvert` bug above).
6. Remove the dis entries from `_SKIP`; generate gwf/gwt/gwe/prt dis and
   disv, and disu. CHF/OLF grids come along if their model modules exist.

### Runtime (`Package`)

- In `__attrs_post_init__`, before broadcasting: convert list/tuple
  griddata to arrays; repeat a size-`nlay` value per layer for `layered`
  arrays; flatten arrays with more than one dimension. Use `self.get_dims()`
  when the package is a `DimensionProvider`, else `dims`. This replaces
  `_coerce_griddata` for every package.

### Mixins

- `DisMethods`: `to_grid`, `from_grid` (built with `cls(...)`, so one
  mixin serves gwf/gwt/gwe/prt).
- `DisvMethods`: `to_grid`, `from_grid`, and the `Cell2d` ↔ grid
  conversion helpers.
- `DisuMethods`: `to_grid`/`from_grid` if `UnstructuredGrid` supports it;
  otherwise none yet.

### Models

- `dis: Dis | Disv | Disu | None` (per model module), and the `convert_grid`
  converters keep dispatching on the grid type.
- `Gwf` file-extension logic (`"disv" if isinstance(..., Disv)`) keeps
  working; could use `dfn_name` instead.

## Decisions

- **Shape mapping stays in flopy4 codegen** (design item 1). The DFN's
  structured shape records how MF6 reads the array, and devtools shouldn't
  drop that; storing griddata flat is flopy4's choice.
- **Accept the generated names and defaults.** `ncf_file` and `grb_file`
  follow the `*_file` convention of every other generated path field
  (`ts_file`, `density_file`, ...). `xorigin`/`yorigin`/`idomain` default to
  `None`, meaning not written, which MF6 treats as 0.0 / all cells active,
  so model behavior is unchanged. Overriding them would mean hand-written
  fields again. Callers reading `dis.idomain` or `dis.xorigin` must handle
  `None`; `to_grid` already does for `idomain`.
- **`nvert` longname:** a DFN fix upstream, described in
  `../modflow6/dfn-nvert-longname.md`.
